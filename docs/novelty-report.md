| 項目 | 内容 |
| --- | --- |
| 対象言語 | Java 21 |
| 難易度プロファイル | 実践・上級 |
| 候補題材 | 基底URI`https://api.example.test/v1/`に`/invoices/42`をresolveし、`/v1/`を失ってホスト直下のURIへ解決する問題 |
| 観測可能な契約 | healthを採用済みの状態で請求書IDをルーティングすると、APIバージョン内のURIを採用し、最後のURIと採用件数を更新すべきだが、バグ状態ではバージョン外として不採用になり、旧状態が残る。 |

| 検索語 | `Java`, `URI.resolve`, `URLエンコード`, `URL解決`, `Path.resolve`, `パス境界`, `先頭スラッシュ` |

## 結論

**作成する。**

Java記事・近接記事にはURLエンコードやCLI引数のエスケープを扱うものがありましたが、`URI.resolve`の**先頭スラッシュが基底URIのAPIバージョンパスを置き換える**ことを直接原因として、ルーティング結果・最後の採用URI・採用件数を扱う記事・教材は見つかりませんでした。

近接するHTTPieのCLI記事とは、文字列内トークンのエスケープか、URIの構造的な参照解決かが異なります。対象言語、実境界、観測契約、最小修正がいずれも独立しているため、教育上意味のある追加題材と判断しました。
